# 路线图

## Phase 0：链路验证（半天，改为自有 echo spike）

写自己的空壳插件 + 官方 SDK 飞书长连接 + 白名单，跑通"飞书 → Mac → 回显"链路
（替代装原版 im-hub 的隔离验证；代码为最终交付物的一部分）。详见
05-implementation-plan.md 第 4 节步骤 1。

## Phase 1：MVP（3-5 周，单人）

- 建仓（本项目）：以 lark-bridge 裁剪为主干（security/state/cards/bridge 移植 + 砍
  CLI/多项目/配对码），im-hub 补设置卡片机制与 mock adapter；飞书通道官方 SDK + 接口隔离
- 飞书长连接 + 白名单
- 内嵌 web profile：发消息 → 当前会话；`/new`
- **审批卡片闭环**（灵魂功能）
- `/status` `/stop` `/resume` `/sessions`

**验收**：飞书完成一次需要审批的真实任务；会话同步出现在 Web GUI；断网重连可用。

## Phase 2：体验完善（1-2 周）

- 话题级多会话映射持久化
- 流式节流与卡片视图优化
- Web GUI 设置卡片
- 超长输出分片 + 链接回 GUI

## Phase 3：按需（视使用情况）

- 文件/图片双向
- 会话空闲自动回收
- 多平台适配

## 工作量说明

MVP 约 80% 零件可从两个参考项目移植，剩余 20% 是"把会话层改接到 web profile 运行时服务"与裁剪。

## 风险提示

两个参考项目均出生不足一周，dsh 为 rc 预览版——本项目自立版本、锁死依赖，不跟随上游节奏。
